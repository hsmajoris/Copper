# Copper 상관관계 대시보드

구리(Copper) 가격과 상관관계가 있는 지표(달러인덱스, 금/구리 비율, WTI, 중국 제조업 PMI,
미국 ISM 제조업 PMI, COMEX 구리 재고)를 한 화면에서 확인하는 Streamlit 대시보드입니다.
[Gold 대시보드](https://github.com/hsmajoris/Gold)와 아키텍처(코드 조직, 배포 방식, UI
레이아웃, 백테스트 구조)를 공유하되, 구리는 안전자산이 아닌 경기민감 산업금속이라는 점을
반영해 지표 구성과 신호 로직을 재설계했습니다.

## 구리가 금과 다른 점 (지표를 다시 설계한 이유)

금 대시보드는 VIX·실질금리 같은 "안전자산 심리" 지표를 사용합니다. 구리는 안전자산이
아니라 산업 수요에 연동되는 경기민감 금속이므로, 이 대시보드는 그 대신 PMI(중국·미국
제조업) 중심의 경기지표를 사용합니다. 또한 지표별로 갱신 주기·신뢰도가 크게 다르기 때문에
(일별 자동 지표 vs. 월간 반자동 PMI vs. 실시간 전용 COMEX 재고), Gold의 "초록불 개수
단순 카운트" 방식 대신 **가중 점수제**로 재설계했습니다.

## 구성

- `copper_dashboard/config.py` — 지표별 구조/의미/상관관계 방향(고정 텍스트), 가중치·임계값
  상수, 출처 각주
- `copper_dashboard/data_sources.py` — yfinance 일별 가격 수집 + PMI best-effort 스크래핑
  (재시도/백오프 포함)
- `copper_dashboard/metrics.py` — 5/30/60일 이동평균·"돌파지속 일수"(일별 지표) 및 "연속
  우호적 개월 수"(PMI) 계산
- `copper_dashboard/signals.py` — 지표별 +1/0/-1 방향 판정과 0~100 가중 점수(`copper_friendly`)
  계산 — 메인 테이블 하이라이트, 차트 음영, 백테스트가 모두 이 모듈의 함수를 호출해 세 곳이
  서로 어긋나지 않도록 함
- `copper_dashboard/build_table.py` — 일별 지표 + PMI 카드 + COMEX 카드 + 종합 점수를 하나의
  payload로 조립
- `copper_dashboard/pmi_store.py` / `comex_store.py` — PMI·COMEX 수동/스크래핑 값을 CSV로
  누적 기록 (날짜와 함께 — 이 누적 기록이 곧 히스토리컬 데이터가 됨)
- `copper_dashboard/update_data.py` — `data/latest.json`을 생성하는 CLI 스크립트 (일별
  지표만 갱신 — PMI/COMEX는 앱의 버튼으로 별도 저장)
- `copper_dashboard/timeseries.py` — 시계열 fetch 공통 모듈 (백테스트와 메인 페이지 그래프가
  함께 사용, `years` 인자로 서로 독립적인 기간 사용)
- `copper_dashboard/backtest.py` — 가중 점수 기반 매매 전략 백테스트 로직
- `app.py` — Streamlit 대시보드 화면 (`st.navigation`/`st.Page` 구성은 Gold와 동일)
- `pages/1_백테스트.py` — 백테스트 결과 페이지 (사이드바 "유효성 검증")
- `.github/workflows/update_dashboard_data.yml` — 매일 07:00(KST) 일별 지표 자동 갱신

## 지표 구성 및 가중치

| 지표 | 방향 | Tier | 가중치 | 자동화 상태 |
|---|---|---|---|---|
| 달러인덱스 (DXY) | 역방향 | A | 1.0 | 완전 자동 |
| 금/구리 비율 (Dr. Copper) | 국면판단(임계값) | A | 0.8 | 완전 자동 |
| 중국 제조업 PMI | 정방향(50 기준선) | C | 0.7 | 버튼 갱신 + 수기 폴백 |
| 미국 ISM 제조업 PMI | 정방향(50 기준선) | C | 0.7 | 버튼 갱신 + 수기 폴백 |
| WTI 유가 | 정방향(약함) | B | 0.4 | 완전 자동 |
| COMEX 구리 재고 | 역방향 | D | 0 (미포함) | **수기 입력만** (아래 참고) |

모든 가중치·임계값은 `copper_dashboard/config.py`의 모듈 상수이며, 코드를 건드리지 않고 그
값만 바꿔 조정할 수 있습니다.

## copper_friendly 가중 점수제

각 지표의 방향 신호(+1 우호적 / 0 중립 / -1 비우호적)에 가중치를 곱해 합산한 뒤, 이론상
최댓값(모든 지표가 +1일 때의 합)을 기준으로 0~100 스케일로 정규화합니다(50 = 중립).

- **일별 SMA 지표(DXY, WTI)**: 5·30·60일 이평선 3개 모두가 동시에 우호적 방향을 가리키면
  +1, 3개 모두 비우호적이면 -1, 엇갈리면 0.
- **금/구리 비율**: 자체 이평선이 아니라 절대 임계값 두 개(`DEFAULT_GC_RATIO_BUY/SELL_THRESHOLD`)
  를 사용 — 비율이 낮으면(금 대비 구리 강세) +1, 높으면(위험회피 국면) -1, 그 사이는 0.
  (메인 테이블의 셀 하이라이트는 Gold와 동일하게 "자체 이평선 대비 위치"를 보여주지만, 이는
  점수 계산과는 별개의 표시입니다 — Gold의 금/은비율과 같은 설계.)
- **PMI**: 50 기준선 초과 시 +1, 미만 시 -1(정확히 50이면 0).
- 갱신일로부터 45일이 지난 PMI는 점수 계산에서 **제외**되고(단순히 0점 처리가 아님),
  남은 지표들의 가중치 합으로 분모를 다시 계산합니다 — "중립"과 "데이터 없음"을 구별하기
  위함입니다.

## 가중치·임계값 산출 근거

작업 시작 시점에 구리 가격 감각이 없는 상태에서 문헌 기반으로 가중치 초안을 잡은 뒤, Phase 1
구현 과정에서 2016~2026년 실제 10년치 데이터(yfinance `HG=F`/`GC=F`/`CL=F`/`DX-Y.NYB`)로
검증했습니다.

- **금/구리 비율 임계값(440 / 620)**: GC=F(트로이온스당 달러)와 HG=F(파운드당 달러)의 단위가
  달라 비율이 수백대 값으로 나오므로(금/은비율 같은 소수 배수가 아님), 실제 10년 일별
  비율의 25번째/75번째 백분위수를 사용했습니다(하위 25% = 우호적, 상위 25% = 비우호적).
- **종합 점수 컷오프(60 / 40)**: 이 값은 의도적으로 **백테스트로 역산하지 않았습니다.**
  PMI 히스토리컬 데이터가 없는 상태에서(아래 참고) DXY·WTI·금구리비율 3개 지표만으로 예비
  백테스트를 돌려보니, 오히려 점수가 높을 때 이후 60일 구리 수익률이 더 낮게 나오는
  **평균회귀(mean-reversion) 패턴**이 관찰되었습니다. 이는 구리 자체 가격이 이미 금/구리
  비율 계산에 들어가 있어 "현재 강세 = 높은 점수"가 순환적으로 발생하기 때문일 수 있고,
  표본이 짧고 PMI가 빠진 예비 결과이기도 합니다. 이 하나의 결과에 맞춰 컷오프를
  최적화하는 것은 과제 요청서가 경고한 바로 그 과최적화이므로, 50(중립) 기준 대칭인 원칙적
  기본값을 유지했습니다. `pages/1_백테스트.py`의 점수 분포 히스토그램으로 이 값을 직접
  조정하며 재검증할 수 있습니다.

## PMI 히스토리컬 데이터 — 설계상 축적형 (문서 초안과의 의도적 차이)

작업 요청서 초안은 "히스토리컬은 비공식 3자 소스를 활용"하는 방식을 제안했지만, Phase 1
조사 결과 신뢰할 수 있는 무료 10년치 PMI 히스토리컬 벌크 데이터 소스를 찾지 못했습니다
(TradingEconomics/investing.com은 최신 수치만 무료로 노출하고, ISM 공식 사이트는 전체
리포트가 SSO 로그인 뒤에 있으며, FRED는 2016년에 ISM 시리즈를 완전히 삭제했습니다). 부정확할
수 있는 3자 데이터를 대량으로 주입하는 대신, **COMEX 재고와 동일한 원칙**을 적용했습니다:
오늘부터 앱의 저장 이력을 축적하고, 백테스트는 그 축적된 데이터가 쌓이는 만큼 자동으로
포함 범위를 넓힙니다.

- `pmi_history.csv`에 12개월 미만이 쌓인 PMI 지표는 백테스트에서 자동 제외되고(가중치도
  분모에서 제외), 12개월 이상 쌓이면 자동으로 포함됩니다(`backtest.MIN_PMI_MONTHS_FOR_BACKTEST`).
  메인 대시보드의 점수 계산은 이 규칙과 무관하게 (staleness 규칙만 적용해) 저장된 값이 있으면
  즉시 반영됩니다 — 백테스트만 "충분한 히스토리"를 요구합니다.
- 이 방식은 요청서가 못박은 "즉시 5개 지표 백테스트"가 아니라 "3개 지표(DXY·WTI·금구리비율)로
  즉시 시작, PMI는 몇 달 안에 자동 편입"으로 동작합니다. 데이터 출처가 검증되지 않은 3자
  소스를 임의로 대량 주입하는 것보다, 이 대시보드 자신이 저장한(스크래핑 성공 시 출처가 실제
  공식 발표를 반영하고, 실패 시 사용자가 직접 확인 후 입력한) 값만 히스토리컬로 쓰는 편이
  안전하다고 판단했습니다.

## COMEX 구리 재고 — 자동 스크래핑 대신 수기 입력 (문서 초안과의 의도적 차이)

요청서 초안은 `cmegroup.com/delivery_reports/Copper_Stocks.xls`를 자동 스크래핑하는 것을
전제로 했지만, 실제로 요청해 보니 **CME Group의 Data Terms of Use상 자동 접근이 명시적으로
금지**되어 있었습니다(HTTP 403과 함께 "This IP address is blocked due to suspected web
scraping activity... strictly prohibited" 응답). 데이터 제공자가 이용약관으로 명시적으로
금지한 엔드포인트를 자동화하는 것은 부적절하다고 판단해, PMI와 같은 저장 패턴이되 **자동
스크래핑 시도 없이 수기 입력만** 지원하도록 구현했습니다. COMEX는 원래부터 백테스트 제외
대상(D tier, 가중치 0)이므로 대시보드의 신호 로직에는 영향이 없습니다.

## PMI 반자동 갱신 UI

- "PMI 새로고침" 버튼 → best-effort 스크래핑(현재는 TradingEconomics 페이지에서 정규식으로
  헤드라인 수치 추출 — 안정된 API가 아니므로 페이지 구조가 바뀌면 조용히 실패) → 성공 시
  입력창에 프리필, 실패 시 에러 없이 빈 채로 두고 수기 입력 유도
- 프리필된 값도 "저장" 버튼을 눌러야 최종 반영(자동 저장 없음)
- 각 PMI 값 옆에 "최종 갱신일 · N일 전" 항상 표시, 45일 초과 시 "데이터 오래됨" 배지와 함께
  점수 계산에서 자동 제외
- 저장된 값은 날짜와 함께 `data/pmi_history.csv`에 누적 기록되고, 저장 즉시(다음 날 배치를
  기다리지 않고) 대시보드 화면과 점수에 반영됩니다

## 백테스트 (유효성 검증)

사이드바의 "유효성 검증" 페이지에서 `copper_friendly` 점수가 설정한 매수/매도 임계값을
넘나들 때 매매하는 전략을 시뮬레이션하고 Buy & Hold와 비교합니다. 매수/매도 조건 UI(카드
분리, 고급설정 접기), 분석 기간 조정(3~10년), 연도별 수익률, 거래 내역 표는 Gold와 동일한
구조입니다. 추가로 점수 분포 히스토그램(컷오프 조정 참고용)과, 이번 실행에 실제로 반영된
지표 목록(PMI 포함 여부)을 표시합니다.

- **COMEX 재고는 백테스트에서 항상 제외됩니다.** 화면에 수집 시작일과 축적 일수가 고정
  표시됩니다.
- **PMI는 위 "PMI 히스토리컬 데이터" 절의 규칙에 따라 자동으로 포함/제외됩니다.**
- 과거 데이터 기반 시뮬레이션으로 미래 성과를 보장하지 않으며, 거래비용·세금·슬리피지는
  반영되지 않았고 표본 기간이 짧아 과최적화 위험이 있습니다. 다변량 모델 기준 표본외
  설명력(R²)은 최대 약 18.5% 수준(2002~2014 LME 데이터 계량연구)이라는 결과도 있어, 개별
  지표 하나로(또는 이들의 단순 가중합으로) 구리값을 예측하는 데는 뚜렷한 한계가 있습니다.

## 지표별 참고 출처 및 한계 (요약)

- 달러인덱스 역상관: 업계 자료 기준 상관계수 약 -0.65~-0.82. CME Group 자료에 따르면
  2000~2019년엔 안정적이었던 관계가 팬데믹 이후 공급망 충격으로 깨진 사례가 있음.
- 금/구리 비율("Dr. Copper"): 시장에서 오래 통용된 경험적 국면판단 지표이며 통계적으로
  검증된 인과관계는 아님.
- WTI 정상관: 문헌상 "약함, 낮은 신뢰도"로 명시된 지표.
- 중국/미국 PMI: HSBC 리서치에 따르면 2022년 러시아-우크라이나 전쟁을 계기로 구리-PMI
  상관관계가 일시적으로 0까지 떨어졌다가 최근 재차 강화되는 등 국면에 따라 크게 변동함.
- 종합: 다변량 모델 기준 표본외 설명력(R²) 최대 약 18.5%(2002~2014 LME 데이터 계량연구).

## 갱신 주기

일별 지표(DXY/WTI/금구리비율)는 GitHub Actions가 매일 22:00 UTC(=07:00 KST)에
`copper_dashboard/update_data.py`를 실행해 `data/latest.json`을 갱신·커밋합니다. PMI·COMEX는
이 배치와 무관하게 앱의 버튼/수기 입력으로 그때그때 갱신되며, 저장 즉시 화면에 반영됩니다.

앱이 "오늘"을 계산할 때는 반드시 `copper_dashboard/timeutil.py`의 `today_kst()`를
사용합니다(서버가 UTC로 동작해도 KST 기준 날짜가 하루 늦게 표시되는 문제 방지).

## 로컬 실행


## 구현 우선순위 (Phase 구분)

**Phase 1 (이번 구현)**
- DXY, WTI, 금/구리비율 완전 자동화
- COMEX 재고 수기 입력 시작 (자동 스크래핑은 CME ToS상 미채택 — 위 참고)

- 가중 점수제 `copper_friendly` 로직(설정 파일로 가중치 분리)
